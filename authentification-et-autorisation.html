    8. Authentification et autorisation

    Deux questions distinctes se posent pour chaque requête :

    • qui est l'utilisateur ? C'est l'authentification : il s'est identifié par un login et un mot de passe, et chaque requête suivante doit prouver qu'elle vient de lui ;
    • a-t-il le droit d'accéder à cette page ? C'est l'autorisation : dans l'étude de cas, seul un utilisateur de rôle ADMIN gère les médecins et les clients.

    Le serveur étant sans état (chapitre 6), la preuve d'identité doit voyager avec chaque requête. On utilise un jeton JWT ([JSON Web Token]) : après la connexion, le serveur fabrique un jeton qui contient l'identité de l'utilisateur et le signe avec une clé secrète. Le jeton est déposé dans un cookie ; le navigateur le renvoie à chaque requête ; le serveur vérifie la signature. L'utilisateur peut lire son jeton, mais pas le modifier : toute modification rend la signature invalide.

    Avec [Spring], ces deux questions sont l'affaire de [Spring Security], un projet de la famille [Spring] distinct de [Spring MVC]. [Spring Security] est une chaîne de filtres de servlet (cf. chapitre 7), placée devant le [DispatcherServlet] : chaque requête la traverse avant d'atteindre [Spring MVC].

    • l'authentification est l'affaire d'un filtre qui cherche un jeton dans la requête, le vérifie et en tire l'utilisateur authentifié, un objet [Authentication] rangé dans le contexte de sécurité de la requête. Pour les jetons JWT, ce filtre est fourni par la partie « serveur de ressources » ([resource server]) de [Spring Security], dont le nom vient du protocole [OAuth2] : un serveur de ressources est un serveur qui accepte des jetons fabriqués par un autre (ici, par lui-même) ;
    • l'autorisation est l'affaire d'un autre filtre, qui applique des règles écrites en [Java] pour chaque URL (« cette adresse est publique », « celle-ci exige un utilisateur authentifié »), et d'annotations posées sur les contrôleurs ([@PreAuthorize], exemple 26).

    Les exemples de ce chapitre utilisent un starter de plus : [spring-boot-starter-security-oauth2-resource-server]. Il apporte [Spring Security], sa partie « serveur de ressources », et la bibliothèque [Nimbus JOSE + JWT], qui fabrique et vérifie les jetons. Le hachage des mots de passe ([bcrypt]) fait partie de [Spring Security] : il n'y a pas d'autre bibliothèque à déclarer. [Maven] télécharge ces bibliothèques à la première compilation : il faut donc une connexion Internet.

    package exemple25.auth;

import java.time.Duration;
import java.time.Instant;
import java.util.Optional;

import org.springframework.http.ResponseCookie;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.oauth2.jose.jws.MacAlgorithm;
import org.springframework.security.oauth2.jwt.JwsHeader;
import org.springframework.security.oauth2.jwt.JwtClaimsSet;
import org.springframework.security.oauth2.jwt.JwtEncoder;
import org.springframework.security.oauth2.jwt.JwtEncoderParameters;
import org.springframework.stereotype.Service;

import exemple25.auth.UtilisateursService.Utilisateur;

@Service
public class AuthService {

    // le nom du cookie qui transporte le jeton
    public static final String COOKIE = "jeton";

    private final UtilisateursService utilisateurs;
    private final PasswordEncoder hachage;
    private final JwtEncoder encodeur;
    private final JwtProprietes proprietes;

    public AuthService(UtilisateursService utilisateurs, PasswordEncoder hachage, JwtEncoder encodeur,
            JwtProprietes proprietes) {
        this.utilisateurs = utilisateurs;
        this.hachage = hachage;
        this.encodeur = encodeur;
        this.proprietes = proprietes;
    }

    // l'utilisateur, ou "rien" si le login est inconnu ou le mot de passe faux
    public Optional<Utilisateur> valider(String login, String motDePasse) {
        if (login == null || motDePasse == null) {
            return Optional.empty();
        }
        return utilisateurs.chercher(login).filter(u -> hachage.matches(motDePasse, u.hachageMotDePasse()));
    }

    // le jeton JWT de l'utilisateur, signé avec la clé secrète
    public String creerJeton(Utilisateur utilisateur) {
        Instant maintenant = Instant.now();
        // le contenu du jeton : les "claims" (affirmations sur l'utilisateur)
        JwtClaimsSet claims = JwtClaimsSet.builder()
                .subject(utilisateur.login())
                .claim("nom", utilisateur.nom())
                .claim("role", utilisateur.role())
                .issuedAt(maintenant)
                .expiresAt(maintenant.plus(duree()))
                .build();
        // l'entête : l'algorithme de signature (HMAC-SHA256)
        JwsHeader entete = JwsHeader.with(MacAlgorithm.HS256).build();
        return encodeur.encode(JwtEncoderParameters.from(entete, claims)).getTokenValue();
    }

    // le cookie qui transporte le jeton : le JavaScript de la page ne peut pas le lire
    public ResponseCookie cookie(String jeton) {
        return ResponseCookie.from(COOKIE, jeton).path("/").httpOnly(true).sameSite("Lax").maxAge(duree()).build();
    }

    private Duration duree() {
        return Duration.ofMinutes(proprietes.dureeMinutes());
    }
}

    Commentons ce code :

    • ligne 22 : le nom du cookie qui transporte le jeton ;
    • lignes 29-35 : le service reçoit par son constructeur le service des utilisateurs, l'encodeur de mots de passe, l'encodeur de jetons [JwtEncoder] et les propriétés [jwt.*]. Ces trois derniers beans sont déclarés dans [SecuriteConfig] ;
    • lignes 38-43 : la vérification du login et du mot de passe. [Optional.filter] vide la boîte si la condition est fausse : le résultat contient l'utilisateur seulement si le login existe et si [hachage.matches(motDePasse, empreinte)] reconnaît le mot de passe ;
    • lignes 49-55 : le contenu du jeton, les claims (affirmations sur l'utilisateur). [subject] (le claim [sub]) est le nom conventionnel de l'identifiant de l'utilisateur. On y met ce dont les pages ont besoin (nom, rôle), pour ne pas relire la base de données à chaque requête. [issuedAt] et [expiresAt] donnent les claims [iat] (date de création) et [exp] (date d'expiration) ;
    • ligne 57 : l'entête du jeton, qui indique l'algorithme de signature : HMAC-SHA256, noté [HS256] ;
    • ligne 58 : l'encodeur fabrique le jeton signé ; [getTokenValue()] en rend la forme texte ;
    • lignes 62-64 : le cookie qui transporte le jeton, fabriqué par la classe [ResponseCookie] de [Spring] : [httpOnly(true)] interdit au [JavaScript] de la page de le lire, ce qui protège le jeton si un script malveillant parvenait à s'exécuter dans la page ; [sameSite("Lax")] empêche le navigateur de le joindre aux requêtes POST émises depuis un autre site (cf. plus bas, la protection [CSRF]) ; [maxAge] donne au cookie la durée de vie du jeton.

        // la chaîne des filtres de sécurité : qui peut accéder à quoi, et comment
    // l'utilisateur est reconnu
    @Bean
    public SecurityFilterChain filtresSecurite(HttpSecurity http) throws Exception {
        http
                // 1. les règles d'accès, examinées dans l'ordre
                .authorizeHttpRequests(acces -> acces
                        .requestMatchers("/", "/login", "/error", "/bootstrap/**").permitAll()
                        .anyRequest().authenticated())
                // 2. l'authentification par jeton JWT ("resource server" OAuth2)
                .oauth2ResourceServer(jwt -> jwt
                        .bearerTokenResolver(jetonDuCookie())
                        .authenticationEntryPoint(versLogin())
                        .jwt(config -> config.jwtAuthenticationConverter(convertisseur())))
                // 3. page protégée demandée sans jeton : direction la page de connexion
                .exceptionHandling(erreurs -> erreurs.authenticationEntryPoint(versLogin()))
                // 4. la déconnexion (POST /logout) : effacer le cookie, puis aller à /login
                .logout(sortie -> sortie.logoutUrl("/logout").deleteCookies(AuthService.COOKIE)
                        .logoutSuccessUrl("/login"))
                // 5. le serveur est sans état : pas de session HTTP
                .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                // 6. pas de jeton anti-CSRF : le cookie SameSite=Lax protège déjà
                // les requêtes POST venues d'autres sites
                .csrf(csrf -> csrf.disable());
        return http.build();
    }

    // le jeton est lu dans le cookie (et non dans l'entête Authorization)
    private static BearerTokenResolver jetonDuCookie() {
        return request -> {
            Cookie cookie = WebUtils.getCookie(request, AuthService.COOKIE);
            return cookie == null ? null : cookie.getValue();
        };
    }

    // pas d'utilisateur authentifié (pas de jeton, jeton invalide ou expiré) :
    // on efface le cookie éventuel et on redirige vers la page de connexion
    private static AuthenticationEntryPoint versLogin() {
        return (request, response, exception) -> {
            if (WebUtils.getCookie(request, AuthService.COOKIE) != null) {
                response.addHeader("Set-Cookie", ResponseCookie.from(AuthService.COOKIE, "").path("/").maxAge(0).build().toString());
            }
            response.sendRedirect("/login");
        };
    }

    // du jeton à l'utilisateur authentifié : le claim [nom] est son nom, le claim
    // [role] son rôle ; Spring Security note les rôles avec le préfixe ROLE_
    private static JwtAuthenticationConverter convertisseur() {
        JwtGrantedAuthoritiesConverter roles = new JwtGrantedAuthoritiesConverter();
        roles.setAuthoritiesClaimName("role");
        roles.setAuthorityPrefix("ROLE_");
        JwtAuthenticationConverter convertisseur = new JwtAuthenticationConverter();
        convertisseur.setJwtGrantedAuthoritiesConverter(roles);
        convertisseur.setPrincipalClaimName("nom");
        return convertisseur;
    }
}

    Commentons ce code :

    • lignes 4-5 : un bean de type [SecurityFilterChain] : la chaîne des filtres de sécurité. [Spring Boot] fournit un objet [HttpSecurity], qu'on règle, méthode après méthode, avant de construire la chaîne (ligne 26). Chaque méthode reçoit une lambda qui règle une partie de la configuration ;
    • lignes 8-10 : les règles d'accès aux URL, examinées dans l'ordre : [/], [/login], [/error] (la page d'erreur de [Spring Boot]) et les fichiers de [Bootstrap] sont publics ([permitAll()]) ; toute autre URL ([anyRequest()]) exige un utilisateur authentifié. La page [/profil] est donc protégée, sans qu'on ait rien à écrire dans son contrôleur ;
    • lignes 12-15 : l'authentification par jeton JWT. Par défaut, le serveur de ressources cherche le jeton dans l'entête [Authorization: Bearer ...] de la requête : c'est ainsi que procède un client [JavaScript] ou une application mobile. Un navigateur n'ajoute pas cet entête de lui-même : on lui indique d'aller chercher le jeton dans le cookie (ligne 13). La ligne 15 remplace la façon dont le jeton devient un utilisateur (cf. lignes 50-58) ;
    • lignes 14 et 17 : le point d'entrée d'authentification ([authentication entry point]) est appelé quand une page protégée est demandée sans utilisateur authentifié. Par défaut, la réponse est une erreur 401, sans contenu : utile à un client [JavaScript], déroutante pour un utilisateur. On redirige vers la page de connexion.     • lignes 19-20 : la déconnexion est prise en charge par [Spring Security] lui-même, par un filtre ([LogoutFilter]) qui intercepte [POST /logout] : il efface le cookie du jeton ([deleteCookies]) et redirige vers [/login]. Aucune action de contrôleur n'est nécessaire ;
    • ligne 22 : [STATELESS] : [Spring Security] ne crée pas de session HTTP (cf. chapitre 6) et ne s'en sert pas pour retenir l'utilisateur. Celui-ci est reconnu, à chaque requête, par le seul jeton ;
    • ligne 25 : la protection [CSRF] ([Cross-Site Request Forgery], falsification de requête inter-sites) est désactivée. Une attaque [CSRF] consiste, pour un site malveillant, à faire envoyer par le navigateur de la victime un formulaire POST vers notre site : le navigateur y joindrait le cookie, et la requête serait authentifiée. Par défaut, [Spring Security] exige dans chaque formulaire POST un jeton anti-CSRF, un champ caché que le site malveillant ne peut pas connaître. Ici, le cookie [SameSite=Lax] suffit : le navigateur ne le joint pas à une requête POST venue d'un autre site, qui arrive donc sans utilisateur authentifié. Il faut en revanche qu'aucune requête GET ne modifie de données (cf. exemple 21) : un cookie [Lax] accompagne les liens venus d'autres sites ;
    • lignes 30-35 : le résolveur du jeton ([BearerTokenResolver]) : une interface à une seule méthode, écrite ici sous forme de lambda, qui rend le jeton de la requête, ou [null]. [WebUtils.getCookie] cherche un cookie par son nom ;
    • lignes 39-46 : le point d'entrée : une redirection vers [/login] (ligne 44). Si la requête portait un cookie [jeton], c'est que le jeton est invalide (signature fausse) ou expiré : on efface le cookie, en le redéposant vide avec une durée de vie nulle (lignes 41-43). Sans cela, le navigateur renverrait le jeton refusé avec la requête [GET /login], que le filtre refuserait à son tour : une boucle de redirections ;
    • lignes 50-58 : du jeton à l'utilisateur authentifié. Pour [Spring Security], les droits d'un utilisateur sont des autorités ([authorities]) : de simples chaînes de caractères. Par défaut, le serveur de ressources les lit dans le claim [scope] du jeton, avec le préfixe [SCOPE_]. On les lit dans le claim [role] (ligne 52), avec le préfixe [ROLE_] (ligne 53), celui que [Spring Security] attend pour un rôle : le rôle [USER] du jeton devient l'autorité [ROLE_USER]. @Service
public class CaptchaService {

    // un captcha : son identifiant, et son image (SVG)
    public record Captcha(String id, String svg) {
    }

    // la réponse attendue, et sa date d'expiration
    private record Attendu(String texte, Instant expire) {
    }

    private static final Duration DUREE_VIE = Duration.ofMinutes(10);

    // identifiant -> réponse attendue.
    // ConcurrentHashMap : un dictionnaire utilisable par plusieurs requêtes simultanées
    private final Map<String, Attendu> enAttente = new ConcurrentHashMap<>();

    public Captcha generer() {
        String texte = DessinCaptcha.texteAleatoire(5);
        String id = UUID.randomUUID().toString(); // un identifiant aléatoire, impossible à deviner
        enAttente.put(id, new Attendu(texte, Instant.now().plus(DUREE_VIE)));
        return new Captcha(id, DessinCaptcha.svg(texte));
    }

    // le captcha est CONSOMMÉ dans tous les cas : une image ne sert qu'une fois
    public boolean verifier(String id, String saisie) {
        Attendu attendu = id == null ? null : enAttente.remove(id);
        return attendu != null && saisie != null
                && attendu.expire().isAfter(Instant.now())
                && attendu.texte().equalsIgnoreCase(saisie.trim());
    }
}

        static String svg(String texte) {
        StringBuilder svg = new StringBuilder();
        svg.append("<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"%d\" height=\"%d\" viewBox=\"0 0 %d %d\">"
                .formatted(LARGEUR, HAUTEUR, LARGEUR, HAUTEUR));
        svg.append("<rect width=\"100%\" height=\"100%\" fill=\"#f5f7fa\"/>");

        // les caractères : chacun agrandi, penché, décalé, et chaque point
        // légèrement déplacé au hasard
        double pas = (LARGEUR - 20) / (double) texte.length();
        for (int i = 0; i < texte.length(); i++) {
            double echelle = hasard(4.6, 5.6); // taille d'une unité de la grille, en pixels
            double angle = hasard(-0.35, 0.35); // rotation, en radians (environ ±20°)
            double cx = 10 + pas * (i + 0.5) + hasard(-3, 3); // centre du caractère
            double cy = HAUTEUR / 2.0 + hasard(-4, 4);
            StringBuilder d = new StringBuilder();
            for (double[] trait : POLICE.get(texte.charAt(i))) {
                for (int k = 0; k < trait.length; k += 2) {
                    // point de la grille, centré sur (2, 3), déformé, tourné, placé
                    double x = (trait[k] - 2 + hasard(-0.2, 0.2)) * echelle;
                    double y = (trait[k + 1] - 3 + hasard(-0.2, 0.2)) * echelle;
                    double px = cx + x * Math.cos(angle) - y * Math.sin(angle);
                    double py = cy + x * Math.sin(angle) + y * Math.cos(angle);
                    d.append(k == 0 ? 'M' : 'L').append(nombre(px)).append(' ').append(nombre(py)).append(' ');
                }
            }
            svg.append("<path d=\"%s\" fill=\"none\" stroke=\"%s\" stroke-width=\"%s\" stroke-linecap=\"round\" stroke-linejoin=\"round\"/>"
                    .formatted(d.toString().trim(), couleur(), nombre(hasard(2.2, 3))));
        }

        // 3 traits de brouillage : des courbes qui traversent l'image
        for (int n = 0; n < 3; n++) {
            svg.append("<path d=\"M%s %s C%s %s %s %s %s %s\" fill=\"none\" stroke=\"%s\" stroke-width=\"1.3\"/>"
                    .formatted(nombre(hasard(0, 20)), nombre(hasard(5, 45)),
                            nombre(hasard(30, 60)), nombre(hasard(0, 50)), nombre(hasard(90, 120)), nombre(hasard(0, 50)),
                            nombre(hasard(130, 150)), nombre(hasard(5, 45)), couleur()));
        }
        svg.append("</svg>");
        return svg.toString();
    }

    // un nombre avec un point décimal, quelle que soit la langue du serveur
    // (en français, "%.1f" écrirait "12,5" - illisible pour SVG)
    private static String nombre(double valeur) {
        return String.format(Locale.ROOT, "%.1f", valeur);
    }

    • lignes 9-28 : chaque caractère devient un chemin [<path>] : une suite de points reliés par des segments ([M] : aller au point, [L] : tracer un segment jusqu'au point). Chaque caractère est agrandi, penché et décalé au hasard, et chacun de ses points légèrement déplacé : deux images du même texte ne sont jamais identiques ;

    package exemple27.auth;

import java.time.Duration;
import java.time.Instant;
import java.util.HashMap;
import java.util.Map;

import org.springframework.stereotype.Service;

// singleton : compte les échecs de connexion de chaque adresse IP
@Service
public class LimiteurService {

    private static final int MAX_ECHECS = 3;
    private static final Duration DUREE_BLOCAGE = Duration.ofMinutes(1);

    private static class Compteur {
        int echecs;
        Instant bloqueJusqua = Instant.MIN;
    }

    private final Map<String, Compteur> compteurs = new HashMap<>();

    // synchronized : plusieurs requêtes simultanées, un seul accès à la fois

    // le nombre de secondes de blocage restantes (0 : pas bloquée)
    public synchronized long secondesBlocage(String ip) {
        Compteur c = compteurs.get(ip);
        if (c == null) {
            return 0;
        }
        Duration reste = Duration.between(Instant.now(), c.bloqueJusqua);
        return reste.isNegative() || reste.isZero() ? 0 : (reste.toMillis() + 999) / 1000;
    }

    public synchronized void echec(String ip) {
        Compteur c = compteurs.computeIfAbsent(ip, cle -> new Compteur());
        c.echecs++;
        if (c.echecs >= MAX_ECHECS) {
            c.bloqueJusqua = Instant.now().plus(DUREE_BLOCAGE);
            c.echecs = 0; // après le blocage, on repart de zéro
        }
    }

    public synchronized void reussite(String ip) {
        compteurs.remove(ip);
    }
}
    • lignes 14-15 : trois échecs bloquent l'adresse IP une minute ;
    • lignes 17-20 : le compteur d'une adresse : nombre d'échecs, et date de fin du blocage ([Instant.MIN], un instant très ancien, au départ) ;
    • ligne 22 : le dictionnaire des compteurs est partagé par toutes les requêtes. C'est un simple [HashMap], qui ne supporte pas les accès simultanés : chaque méthode est donc [synchronized]. Le mot-clé garantit qu'un seul thread à la fois exécute l'une des méthodes [synchronized] de l'objet : deux échecs simultanés ne peuvent pas se perdre (cf. [AtomicInteger], chapitre 6) ;
    • lignes 27-34 : le temps de blocage restant, arrondi à la seconde supérieure ;
    • lignes 36-43 : un échec est compté ; au troisième, l'adresse est bloquée. [computeIfAbsent] rend le compteur de l'adresse, après l'avoir créé s'il n'existait pas ;
    • lignes 45-47 : une réussite efface le compteur.

import java.util.Optional;

import org.springframework.http.HttpHeaders;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;

import org.springframework.web.bind.annotation.PostMapping;

import exemple27.auth.AuthService;
import exemple27.auth.CaptchaService;
import exemple27.auth.LimiteurService;
import exemple27.auth.UtilisateursService.Utilisateur;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@Controller
public class AuthController {

    private final AuthService auth;
    private final CaptchaService captchas;
    private final LimiteurService limiteur;

    public AuthController(AuthService auth, CaptchaService captchas, LimiteurService limiteur) {
        this.auth = auth;
        this.captchas = captchas;
        this.limiteur = limiteur;
    }

    @GetMapping("/")
    public String accueil() {
        return "redirect:/profil";
    }

    @GetMapping("/login")
    public String formulaire(Model model) {
        return login(model, null, null);
    }

    @PostMapping("/login")
    public String connexion(@RequestParam(required = false) String login,
            @RequestParam(required = false) String motDePasse, @RequestParam(required = false) String captchaId,
            @RequestParam(required = false) String captcha, HttpServletRequest request,
            HttpServletResponse response, Model model) {
        // l'adresse IP du client
        String ip = request.getRemoteAddr();

        // 1. une adresse bloquée n'est même pas écoutée
        long secondes = limiteur.secondesBlocage(ip);
        if (secondes > 0) {
            return login(model, login, "Trop de tentatives : réessayez dans " + secondes + " s.");
        }
        // 2. le captcha d'abord (peu coûteux), le mot de passe (bcrypt, coûteux) ensuite
        if (!captchas.verifier(captchaId, captcha)) {
            limiteur.echec(ip);
            return login(model, login, "Le code de l'image est incorrect.");
        }
        Optional<Utilisateur> utilisateur = auth.valider(login, motDePasse);
        if (utilisateur.isEmpty()) {
            limiteur.echec(ip);
            return login(model, login, "Login ou mot de passe incorrect.");
        }
        limiteur.reussite(ip);
        response.addHeader(HttpHeaders.SET_COOKIE, auth.cookie(auth.creerJeton(utilisateur.get())).toString());
        return "redirect:/profil";
    }

    // chaque affichage du formulaire fabrique un NOUVEAU captcha
    private String login(Model model, String login, String erreur) {
        model.addAttribute("login", login);
        model.addAttribute("erreur", erreur);
        model.addAttribute("captcha", captchas.generer());
        return "auth/login";
    }
}
