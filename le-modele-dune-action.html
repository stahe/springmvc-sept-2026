    3. Le modèle d'une action

    Une action a besoin des informations envoyées par le navigateur : les paramètres de l'URL ([?nom=martin&age=42]), les champs d'un formulaire, le corps JSON d'une requête, parfois un entête HTTP. Le cours d'origine appelle modèle de l'action l'ensemble de ces informations. Ce chapitre montre comment [Spring MVC] les fournit à l'action, les convertit dans le bon type et les valide. Ce travail s'appelle la liaison de données ([data binding]).

    Attention au vocabulaire : dans [Spring MVC], le mot « modèle » ([Model]) désigne surtout les données qu'une action transmet à sa vue (chapitre 4, « La vue et son modèle »). Le modèle d'une action, au sens de ce chapitre, est ce qu'elle reçoit.

    Les exemples 07 à 12 sont, comme ceux du chapitre précédent, des modules [Maven] du dossier [exemples]. On lance l'un d'eux en ouvrant un terminal sur son dossier et en tapant [../mvnw spring-boot:run] ([..\mvnw spring-boot:run] sous [Windows]) ; [Ctrl-C] arrête le serveur. Chaque exemple a un fichier [application.properties] de ce genre :

    package exemple07.controllers;

import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/parametres")
public class ParametresController {

    // /parametres/action01?nom=martin : le paramètre [nom] de l'URL -> le paramètre [nom] de l'action
    // required = false : le paramètre peut manquer, il vaut alors null
    @GetMapping("/action01")
    public String action01(@RequestParam(required = false) String nom) {
        return "nom = [%s], de type %s".formatted(nom, nom == null ? "null" : nom.getClass().getSimpleName());
    }

    // /parametres/action02?age=42 : la valeur est CONVERTIE dans le type du paramètre ;
    // sans required = false, le paramètre est obligatoire
    @GetMapping("/action02")
    public String action02(@RequestParam int age) {
        return "age = [%d], de type int".formatted(age);
    }

    // /parametres/action03?age=42 : Integer (et non int) accepte la valeur null
    @GetMapping("/action03")
    public String action03(@RequestParam(required = false) Integer age) {
        return "age = [%s]".formatted(age);
    }

    // /parametres/action04?page=2 : une valeur par défaut si le paramètre manque
    @GetMapping("/action04")
    public String action04(@RequestParam(defaultValue = "1") int page) {
        return "page = [%d]".formatted(page);
    }

    // /parametres/action05?q=spring : le nom du paramètre de l'URL, quand il diffère
    @GetMapping("/action05")
    public String action05(@RequestParam(name = "q", required = false) String recherche) {
        return "recherche = [%s]".formatted(recherche);
    }

    // /parametres/action06?nom=martin&age=42 : tous les paramètres d'un coup
    @GetMapping("/action06")
    public Map<String, String> action06(@RequestParam Map<String, String> parametres) {
        return parametres;
    }
}

    Commentons ce code :

    • lignes 16-17 : l'annotation [@RequestParam] associe un paramètre de l'action à un paramètre de l'URL (la partie qui suit le [?], appelée chaîne de requête ou [query string]). Sans autre précision, le paramètre de l'URL porte le même nom que le paramètre [Java] : [nom]. Ce nom n'est connu à l'exécution que parce que le projet parent de [Spring Boot] demande au compilateur de le conserver dans le code compilé (option [-parameters]). Une annotation peut recevoir des arguments nommés, appelés attributs : [required = false] indique que le paramètre peut manquer ; il vaut alors [null]. Ligne 18 : la méthode [formatted] remplace chaque [%s] de la chaîne par l'argument suivant ; [nom.getClass().getSimpleName()] est le nom court du type de la valeur ;
    • lignes 23-24 : le paramètre est déclaré de type [int] : [Spring MVC] convertit la chaîne reçue (["42"]) en nombre. Sans l'attribut [required = false], [@RequestParam] rend le paramètre obligatoire : c'est la valeur par défaut de [required]. Un paramètre absent, ou dont la conversion échoue, provoque une erreur 400, et l'action n'est pas exécutée ;
    • lignes 29-30 : un [int] ne peut pas valoir [null]. Pour un nombre facultatif, on déclare le paramètre avec le type [Integer], la classe [Java] qui « enveloppe » un [int] ([wrapper]) : un objet [Integer] peut valoir [null], ce qui permet de distinguer « pas d'âge » de « âge 0 » ;
    • lignes 35-36 : l'attribut [defaultValue] fournit la valeur à utiliser quand le paramètre manque (il rend aussi le paramètre facultatif). C'est une chaîne, convertie comme le serait la valeur reçue ;
    • lignes 41-42 : l'attribut [name] donne le nom du paramètre de l'URL quand il diffère de celui du paramètre [Java] : le paramètre [recherche] de l'action reçoit le paramètre [q] de l'URL ;
    • lignes 47-48 : un paramètre de type [Map<String, String>] annoté [@RequestParam] reçoit tous les paramètres de l'URL, sans conversion : un dictionnaire (nom du paramètre, valeur). L'action le renvoie tel quel, et [Spring MVC] le sérialise en JSON.

    package exemple08.models;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

// le modèle de l'action : une classe dont chaque champ porte ses contraintes
public class PersonneModele {

    @NotBlank(message = "le nom est obligatoire")
    @Size(min = 2, max = 20, message = "le nom doit avoir de 2 à 20 caractères")
    private String nom;

    @NotNull(message = "l'âge est obligatoire")
    @Min(value = 0, message = "l'âge doit être compris entre 0 et 150")
    @Max(value = 150, message = "l'âge doit être compris entre 0 et 150")
    private Integer age;

    @NotNull(message = "le titre est obligatoire")
    @Pattern(regexp = "Mr|Mme|Melle", message = "titre inconnu")
    private String titre;

    // facultatif : pas de @NotNull
    @Email(message = "adresse électronique invalide")
    private String email;

    // les accesseurs (getters et setters) : la liaison de modèle remplit
    // chaque champ par son setter ; la sérialisation JSON le lit par son getter
    public String getNom() { return nom; }
    public void setNom(String nom) { this.nom = nom; }

    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }

    public String getTitre() { return titre; }
    public void setTitre(String titre) { this.titre = titre; }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
}

    Commentons ce code :

    • lignes 3-9 : les annotations de validation, toutes dans le package [jakarta.validation.constraints] ;
    • lignes 14-16 : le nom est obligatoire et non vide ([@NotBlank] refuse [null], la chaîne vide et une chaîne faite d'espaces) et doit avoir de 2 à 20 caractères ([@Size]). Chaque annotation accepte un message d'erreur personnalisé (attribut [message]) ;
    • lignes 18-21 : l'âge est converti en entier, obligatoire ([@NotNull]), compris entre 0 et 150 ([@Min], [@Max]). Il est déclaré [Integer] et non [int], pour que « pas d'âge » ([null]) soit détecté par [@NotNull] au lieu de devenir 0 ;
    • lignes 23-25 : le titre doit vérifier l'expression régulière [Mr|Mme|Melle] ([@Pattern]) : il doit être l'une de ces trois valeurs ;
    • lignes 28-29 : l'adresse électronique est facultative (pas de [@NotNull]) ; si elle est présente, elle doit être valide ([@Email]). Toutes les contraintes autres que [@NotNull] et [@NotBlank] acceptent la valeur [null] : c'est ce qui rend un champ facultatif ;
    • lignes 33-43 : les accesseurs. Par convention, la valeur du champ [nom] se lit par la méthode [getNom] ([getter]) et s'écrit par la méthode [setNom] ([setter]). Une classe qui a un constructeur sans paramètre (ici, celui que [Java] fournit implicitement) et des accesseurs qui suivent cette convention s'appelle un JavaBean. C'est la forme qu'attend la liaison de données : [Spring MVC] crée l'objet avec son constructeur sans paramètre, puis, pour chaque paramètre de la requête, appelle le setter de même nom : [setNom("martin")] pour [?nom=martin], après avoir converti la valeur dans le type du setter. Le convertisseur JSON, lui, lit les champs par leurs getters.

    package exemple08.controllers;

import java.util.LinkedHashMap;
import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import exemple08.models.PersonneModele;
import jakarta.validation.Valid;

@RestController
@RequestMapping("/personnes")
public class PersonnesController {

    // /personnes/action01?nom=martin&age=42&titre=Mr
    // @Valid : le modèle est validé AVANT l'exécution de l'action ; s'il est
    // invalide, la requête est refusée AUTOMATIQUEMENT (erreur 400)
    @GetMapping("/action01")
    public Map<String, Object> action01(@Valid PersonneModele personne) {
        Map<String, Object> reponse = new LinkedHashMap<>();
        reponse.put("personne", personne);
        reponse.put("typeAge", personne.getAge().getClass().getSimpleName());
        return reponse;
    }
}

Le paramètre est alors un objet de commande ([command object]), créé et rempli par la liaison de données comme on vient de le décrire. Les paramètres de la requête qui ne correspondent à aucun setter sont ignorés ;
    • ligne 21 : l'annotation [@Valid] (de [jakarta.validation]) demande de valider l'objet après l'avoir rempli, en vérifiant les contraintes de ses champs. Si la liaison ou la validation échoue, [Spring MVC] lève l'exception [MethodArgumentNotValidException] : l'action n'est pas exécutée et la réponse est une erreur 400. C'est l'équivalent de l'attribut [[ApiController]] d'[ASP.NET Core MVC] ;
    • lignes 22-25 : l'action rend la personne reçue et le type de son âge. [LinkedHashMap] est un dictionnaire qui garde l'ordre d'insertion de ses clés : le JSON produit les aura dans cet ordre.

    3.2.1. Pourquoi une classe JavaBean et pas un record ?

    Depuis [Java] 16, un record décrit en une ligne une classe de données non modifiable : [record Point(int x, int y) {}] déclare les champs [x] et [y], un constructeur qui les reçoit tous, et les méthodes de lecture [x()] et [y()].     // exécutée, et c'est elle qui décide de ce qu'elle fait d'un modèle invalide
    @GetMapping(value = "/action01", produces = MediaType.TEXT_HTML_VALUE)

    • ligne 20 : l'attribut [produces] de [@GetMapping] fixe le type de la réponse : [MediaType.TEXT_HTML_VALUE] est la constante ["text/html"]. La chaîne rendue par l'action est donc envoyée comme une page HTML ;
    • ligne 21 : l'action a un second paramètre, de type [BindingResult], placé juste après le modèle validé.     • lignes 27-29 : sinon, la liste des erreurs. L'argument de [map] est une lambda : une fonction anonyme, écrite [paramètre -> expression] ;

        reponse.put("erreurs", resultat.getAllErrors().stream().map(ObjectError::getDefaultMessage).sorted().toList());
        return reponse;
    }
}

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;
import java.time.format.ResolverStyle;

import org.springframework.core.convert.converter.Converter;

// un convertisseur : transforme une date française "23/09/2026" en LocalDate.
// Il sera utilisé pour TOUT paramètre de type LocalDate (cf. WebConfig)
public class DateFrConverter implements Converter<String, LocalDate> {

    // uuuu : l'année ; STRICT : "31/02/2026" est refusée (et non ramenée au 28 février)
    private static final DateTimeFormatter FORMAT =
            DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT);

    public LocalDate convert(String texte) {

            return LocalDate.parse(texte, FORMAT);

            // échec : une exception, que Spring transforme en erreur de conversion
            throw new IllegalArgumentException("[" + texte + "] n'est pas une date jj/mm/aaaa valide");
        }
    }
}

import org.springframework.core.MethodParameter;
import org.springframework.web.bind.support.WebDataBinderFactory;
import org.springframework.web.context.request.NativeWebRequest;
import org.springframework.web.method.support.HandlerMethodArgumentResolver;

// un "argument resolver" : il fournit la valeur des paramètres annotés @Langue,
// lue dans l'entête "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LangueResolver implements HandlerMethodArgumentResolver {

    // ce resolver s'occupe-t-il de ce paramètre ?
    @Override
    public boolean supportsParameter(MethodParameter parametre) {
        return parametre.hasParameterAnnotation(Langue.class) && parametre.getParameterType() == String.class;

    // la valeur du paramètre
    @Override
    public Object resolveArgument(MethodParameter parametre, ModelAndViewContainer mavContainer,

        String entete = requete.getHeader("Accept-Language");
        String premiere = entete == null ? "" : entete.split(",")[0].trim();
        return premiere.length() >= 2 ? premiere.substring(0, 2).toLowerCase() : "fr";
    }
}

    3.6.6. Conclusion

    Le modèle d'une action est construit par la liaison de données à partir de la requête : paramètres de l'URL et champs du formulaire ([@RequestParam], objet de commande), corps JSON ([@RequestBody]), entêtes ([@RequestHeader]), et tout ce qu'un résolveur personnalisé sait fournir. Les valeurs sont converties dans le type des paramètres, puis validées par les contraintes [Bean Validation] quand le modèle est annoté [@Valid]. Une erreur de conversion d'un [@RequestParam], ou un modèle invalide sans [BindingResult], donne une erreur 400 sans exécuter l'action : cela convient à un serveur JSON. Pour une application HTML, le formulaire est un JavaBean annoté [@Valid], suivi d'un paramètre [BindingResult] que l'action consulte (exemple 09), afin de pouvoir réafficher le formulaire avec ses erreurs. C'est l'objet du chapitre suivant.
