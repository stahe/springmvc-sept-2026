    4. La vue et son modèle

    Jusqu'ici, les actions fabriquaient elles-mêmes leur réponse : du texte, du JSON, quelques balises HTML écrites dans une chaîne de caractères. Dans une application MVC, c'est le rôle d'une vue : un fichier qui décrit la page HTML, avec des emplacements pour les données que lui transmet l'action, le modèle de la vue. [Spring MVC] ne fournit pas lui-même de langage de vues : il sait travailler avec plusieurs moteurs de vues ([Thymeleaf], [FreeMarker], [Mustache], [JSP]...). Ce cours utilise [Thymeleaf], le moteur de vues le plus répandu avec [Spring MVC], que [Spring Boot] sait configurer tout seul.

    Une vue [Thymeleaf] est un fichier [.html] ordinaire : un fichier HTML valide, que l'on peut ouvrir tel quel dans un navigateur. Les données y sont insérées par des attributs supplémentaires, préfixés par [th:] ([th:text], [th:if], [th:each]...), que [Thymeleaf] exécute sur le serveur, puis retire de la page. C'est ce que [Thymeleaf] appelle des modèles naturels ([natural templates]) : un graphiste peut travailler sur la vue sans lancer l'application, et le développeur y ajoute les attributs [th:]. C'est une différence avec [Razor], le moteur de vues d'[ASP.NET Core MVC], qui mélange HTML et code [C#] précédé du caractère [@].

    package exemple13.controllers;

import java.time.LocalTime;
import java.time.format.DateTimeFormatter;
import java.util.Map;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.servlet.ModelAndView;

import exemple13.models.PageModele;

// @Controller : les actions rendent le NOM d'une vue
@Controller
public class VuesController {

    private static final DateTimeFormatter HEURE = DateTimeFormatter.ofPattern("HH:mm:ss");

    // Model : le modèle de la vue, un dictionnaire rempli par l'action ;
    // la chaîne rendue est le nom de la vue : templates/vues/index.html
    @GetMapping("/")
    public String index(Model model) {
        PageModele modele = new PageModele(
                "Ma première vue",
                "Cette page a été fabriquée par Thymeleaf, sur le serveur.",
                LocalTime.now().format(HEURE));
        model.addAttribute("modele", modele);
        return "vues/index";
    }

    // ModelAndView : la vue, son modèle et, si besoin, le code de la réponse, en un seul objet
    @GetMapping("/bonjour/{nom}")
    public ModelAndView bonjour(@PathVariable String nom) {
        if (nom.equals("inconnu")) {
            return new ModelAndView("vues/inconnu", Map.of("nom", nom), HttpStatus.NOT_FOUND);
        }
        PageModele modele = new PageModele(
                "Bonjour " + nom,
                "Cette fois, l'action a construit un objet ModelAndView.",
                LocalTime.now().format(HEURE));
        return new ModelAndView("vues/index", Map.of("modele", modele));
    }
}

    Commentons ce code :

    • ligne 17 : l'annotation [@Controller] remplace l'annotation [@RestController] des exemples précédents. Avec [@RestController], ce que rend une action est la réponse (du texte, du JSON). Avec [@Controller], une action qui rend une chaîne de caractères rend le nom d'une vue : c'est la vue qui fabriquera la réponse ;
    • ligne 25 : l'action reçoit un paramètre de type [Model], fourni par [Spring MVC]. C'est le modèle de la vue : un dictionnaire, dont chaque entrée (un attribut) associe un nom à un objet ;
    • lignes 26-30 : l'action fabrique un objet [PageModele] (un titre, un message, l'heure courante) et le range dans le modèle sous le nom [modele]. C'est sous ce nom que la vue le retrouvera ;
    • ligne 31 : l'action rend le nom de la vue, [vues/index]. Elle ne fabrique plus la réponse : elle désigne une vue et lui a préparé ses données ;
    • ligne 36 : l'action [bonjour] rend un objet [ModelAndView], qui réunit en un seul objet le nom de la vue et son modèle. C'est l'autre façon d'écrire une action qui utilise une vue ;
    • ligne 38 : quand la vue dépend de la requête, l'action choisit la vue. Ici, le nom [inconnu] affiche la vue [vues/inconnu], avec le code 404 : le troisième argument du constructeur de [ModelAndView] est le code de la réponse. Le modèle de cette vue contient une simple chaîne, le nom demandé. [Map.of(...)] fabrique un dictionnaire non modifiable ;
    • ligne 44 : les deux actions partagent la même vue [vues/index], avec des modèles différents.

    Où [Spring MVC] cherche-t-il la vue [vues/index] ? Il confie le nom de la vue à un résolveur de vues ([ViewResolver]), qui le transforme en une vue concrète. Celui que configure [Spring Boot] pour [Thymeleaf] ([ThymeleafViewResolver]) ajoute au nom un préfixe, [classpath:/templates/], et un suffixe, [.html] : la vue [vues/index] est le fichier [templates/vues/index.html] du classpath, c'est-à-dire des dossiers et archives où la machine virtuelle [Java] cherche les classes et les ressources de l'application. Le dossier [src/main/resources] du projet en fait partie : son contenu est copié par [Maven] dans [target/classes], à côté des classes compilées. Ces deux valeurs peuvent être changées dans [application.properties] (propriétés [spring.thymeleaf.prefix] et [spring.thymeleaf.suffix]). Contrairement à [ASP.NET Core MVC], il n'y a pas de convention qui déduirait le nom de la vue du nom du contrôleur et de l'action : l'action donne toujours le chemin de la vue, relatif au dossier [templates].     Commentons ce code :

    • ligne 2 : un commentaire [Thymeleaf] s'écrit [<!--/* ... */-->]. C'est un commentaire HTML dont le contenu est encadré par [/*] et [*/] : [Thymeleaf] le retire de la page produite, alors qu'un commentaire HTML ordinaire [<!-- -->] serait envoyé au navigateur ;
    • ligne 3 : l'attribut [xmlns:th] déclare l'espace de noms des attributs [th:]. Il ne sert qu'aux éditeurs de code (complétion, vérification) : [Thymeleaf] traite les attributs [th:] même sans lui, et le retire de la page produite ;
    • ligne 6 : l'attribut [th:text] remplace le contenu de la balise par la valeur de l'expression. [${modele.titre}] est une expression de variable : [modele] est l'attribut du modèle déposé par l'action, [.titre] appelle son accesseur [titre()]. Le texte « Titre de la page » écrit dans la balise n'est qu'un exemple, affiché si l'on ouvre le fichier directement dans un navigateur ; il disparaît de la page produite ;
    • lignes 9-11 : même principe pour le titre, le message et l'heure. Pour insérer une valeur au milieu d'un texte, on l'enveloppe dans une balise [<span>], qui porte l'attribut [th:text].

    Les expressions [${...}] sont écrites dans le langage d'expressions de [Spring], [SpEL] ([Spring Expression Language]). [modele.titre] appelle la méthode [getTitre()] d'un [JavaBean], ou la méthode [titre()] d'un record : on écrit la même chose dans les deux cas.

    Une vue [Thymeleaf] n'est pas compilée avec l'application : elle est lue et interprétée au moment où la page est demandée. Une erreur dans une vue n'est donc pas signalée à la compilation, mais à l'affichage de la page. Si l'on écrit [${modele.titr}] dans la vue, la requête échoue (code 500) et la console du serveur affiche : [Property or field 'titr' cannot be found on object of type 'exemple13.models.PageModele']. De même, un nom de vue qui ne correspond à aucun fichier provoque l'erreur [Error resolving template [vues/absente], template might not exist or might not be accessible by any of the configured Template Resolvers].     Commentons ce code :

    • ligne 8 : l'attribut [th:with] déclare des variables locales, utilisables dans la balise qui le porte et dans toutes ses descendantes : ici [total] et [nombre], dans tout le corps de la page. [modele.produits.![prix]] est une projection [SpEL] : la liste des prix des produits. [#aggregates] et [#lists] sont des objets utilitaires de [Thymeleaf] (ils commencent par [#]) : [#aggregates.sum] fait la somme d'une liste de nombres, [#lists.size] compte les éléments d'une liste ;
    • lignes 10-11 : un commentaire [Thymeleaf], absent de la page produite ;
    • ligne 12 : une valeur [null] ([${modele.surnom}]) n'affiche rien, sans erreur ;
    • lignes 14-15 : [th:text] échappe les caractères spéciaux du HTML ([<] devient [&lt;]...) : le texte s'affiche tel quel. [th:utext] ([unescaped text]) l'insère sans échappement : il est interprété comme du HTML. On n'utilise [th:utext] que pour du HTML fabriqué par l'application, jamais pour une donnée saisie par un utilisateur : celui-ci pourrait injecter du HTML, voire du [JavaScript], dans la page (attaque dite [XSS], [cross-site scripting]) ;
    • lignes 17-18 : une condition. [th:if] garde la balise (et son contenu) si l'expression est vraie, et la supprime sinon ; [th:unless] fait l'inverse. Il n'y a pas de [th:else] : on écrit la condition contraire ;
    • ligne 22 : une boucle. L'attribut [th:each] répète la balise qui le porte, ici [<li>], une fois par élément de la liste. [produit] est l'élément courant ; [stat], facultatif, est l'état de l'itération : [stat.index] (à partir de 0), [stat.count] (à partir de 1), [stat.size], [stat.first], [stat.last], [stat.even], [stat.odd].     • ligne 23 : l'opérateur conditionnel [condition ? valeur1 : valeur2]. Les chaînes littérales s'écrivent entre apostrophes ;
    • lignes 24-25 : [th:block] est une balise propre à [Thymeleaf] : elle ne sert qu'à porter des attributs [th:] et disparaît de la page produite, en ne laissant que son contenu. [stat.first] et [stat.last] testent la position dans la boucle ;
    • lignes 30-31 : le cas de la liste vide. [#lists.isEmpty] teste si la liste est vide ; une boucle [th:each] sur une liste vide ne produit rien ;
    • ligne 34 : une substitution littérale [|...|] qui utilise les variables de [th:with], et deux appels de méthodes : [total.doubleValue()] convertit le [BigDecimal] en [double], et [#numbers.formatDecimal(valeur, 1, 2)] formate un nombre avec au moins un chiffre avant la virgule et exactement deux après ;
    • ligne 35 : un chemin pointé [modele.adresse.rue], et l'objet utilitaire [#strings], qui regroupe les opérations sur les chaînes ([toUpperCase], [isEmpty], [contains], [startsWith]...) ;
    • ligne 36 : [Thymeleaf] ne traite que les attributs [th:] et les expressions en ligne [[[...]]] : le reste du texte est recopié tel quel. Le caractère [@] n'a ici aucun sens particulier.

import org.thymeleaf.context.ITemplateContext;
import org.thymeleaf.context.IWebContext;

// le processeur de l'attribut ex:actif : <a href="/produits" ex:actif="/produits">
// reçoit la classe "active" si la page courante est sous ce chemin
public class ActifProcessor extends AbstractAttributeTagProcessor {

    public ActifProcessor(String prefixe) {
        // HTML ; balises <a> seulement ; attribut [ex:actif] ; priorité ; true : l'attribut
        // ex:actif est retiré de la page produite
        super(TemplateMode.HTML, prefixe, "a", false, "actif", true, 1000, true);
    }

    // appelée pour chaque balise <a> qui porte l'attribut ex:actif
    @Override
    protected void doProcess(ITemplateContext contexte, IProcessableElementTag balise,
            AttributeName nomAttribut, String valeur, IElementTagStructureHandler structure) {
        // le chemin de la page, lu dans la requête en cours
        String chemin = contexte instanceof IWebContext web ? web.getExchange().getRequest().getRequestPath() : "";
        boolean estActif = valeur.equals("/") ? chemin.equals("/") : chemin.startsWith(valeur);
        if (estActif) {
            // on ajoute la classe "active" à l'attribut class de la balise
            String classes = balise.getAttributeValue("class");
            structure.setAttribute("class", classes == null ? "active" : classes + " active");
        }
    }
}

            new Livre("Le Rouge et le Noir", "Stendhal", "roman"),
            new Livre("Les Fleurs du mal", "Baudelaire", "poésie"),
            new Livre("Madame Bovary", "Flaubert", "roman"),

    private static final List<String> GENRES = List.of("roman", "poésie", "théâtre");

    // GET / et GET /recherche?motCle=...&genre=... : le formulaire ET ses résultats
    @GetMapping({ "/", "/recherche" })
    public String recherche(@RequestParam(required = false) String motCle,
            @RequestParam(required = false) String genre, Model model) {
        String mot = motCle == null ? "" : motCle.trim().toLowerCase(Locale.ROOT);
        List<Livre> resultats = LIVRES.stream()
                .filter(l -> mot.isEmpty() || l.titre().toLowerCase(Locale.ROOT).contains(mot)
                        || l.auteur().toLowerCase(Locale.ROOT).contains(mot))
                .filter(l -> genre == null || genre.isEmpty() || l.genre().equals(genre))
                .toList();
        model.addAttribute("modele", new RechercheModele(motCle == null ? "" : motCle,
                genre == null ? "" : genre, GENRES, resultats));
        return "livres/recherche";
    }

    4.7.2. La validation par le navigateur

    Les attributs [required], [maxlength], [min], [max], [type="email"]... demandent au navigateur de vérifier le formulaire avant de l'envoyer : l'utilisateur est prévenu immédiatement, par une bulle d'aide, sans aller-retour avec le serveur. C'est le comportement obtenu avec le lien « l'activer » (http://localhost:5000/inscription?html5=true), qui retire l'attribut [novalidate] du formulaire.

    Cette validation est un confort, pas une protection : il suffit de retirer l'attribut [required] avec les outils de développement du navigateur, ou d'envoyer la requête avec [curl], pour la contourner. La validation par le serveur reste indispensable. C'est pourquoi l'exemple désactive par défaut la validation du navigateur : pour voir travailler le serveur. L'étude de cas, elle, garde les deux : les attributs HTML5 pour le confort, et la validation serveur pour la sûreté.

    4.8. Exemple 20 : le schéma Post / Redirect / Get

    Quand un formulaire POST réussit, l'action peut afficher directement une page. Le problème apparaît si l'utilisateur recharge ensuite cette page (touche F5) : le navigateur renvoie le formulaire, et l'opération est faite une seconde fois (une commande passée deux fois, un rendez-vous pris deux fois...). Le schéma Post / Redirect / Get (PRG) évite ce problème : une action POST réussie ne fabrique pas de page, elle redirige vers une page GET. Recharger cette page ne refait qu'un GET, sans effet.

    Reste un détail : la page GET doit afficher un message (« la tâche a été ajoutée »), alors que ce message a été produit par l'action POST, dans une autre requête. [Spring MVC] fournit pour cela les attributs flash : des attributs déposés avant la redirection, qui survivent jusqu'à la requête suivante, où ils sont ajoutés au modèle, puis disparaissent. C'est ce qu'on appelle un message flash. Par défaut, [Spring MVC] conserve les attributs flash dans la session HTTP de l'utilisateur : une mémoire que le serveur associe à chaque navigateur (le chapitre « Portées des données » lui est consacré).

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import exemple20.services.TachesService;

@Controller
@RequestMapping("/taches")
public class TachesController {

    private final TachesService taches;

    public TachesController(TachesService taches) {
        this.taches = taches;
    }

    // GET /taches : la liste et le formulaire d'ajout
    @GetMapping("")
    public String afficher(Model model) {
        model.addAttribute("taches", taches.liste());
        return "taches/taches";
    }

    // POST /taches : le schéma Post / Redirect / Get
    @PostMapping("")
    public String ajouter(@RequestParam(required = false) String libelle, Model model,
            RedirectAttributes redirection) {
        String texte = libelle == null ? "" : libelle.trim();
        if (texte.isEmpty() || texte.length() > 40) {
            // saisie invalide : on réaffiche la page, sans redirection
            model.addAttribute("libelle", libelle);
            model.addAttribute("erreur", "Le libellé doit comporter de 1 à 40 caractères.");
            return afficher(model);
        }
        taches.ajouter(texte);
        // un attribut "flash" : il survivra à la redirection, pour la requête SUIVANTE
        redirection.addFlashAttribute("flash", "La tâche [" + texte + "] a été ajoutée.");
        // pas de page : une redirection vers la page GET
        return "redirect:/taches";
    }

    // POST /taches/sans-prg : le contre-exemple (une page en réponse au POST)
    @PostMapping("/sans-prg")
    public String ajouterSansPrg(@RequestParam(required = false) String libelle, Model model) {
        taches.ajouter(libelle == null || libelle.isBlank() ? "(sans titre)" : libelle.trim());
        model.addAttribute("sansPrg", true);
        return afficher(model);
    }
}

    package exemple21.services;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

import org.springframework.stereotype.Service;

// les contacts, en mémoire, partagés par tous (singleton)
@Service
public class ContactsService {

    // un contact : un identifiant, un nom, un numéro de téléphone
    public record Contact(int id, String nom, String telephone) {
    }

    private final List<Contact> contacts = new ArrayList<>(List.of(
            new Contact(1, "Marie Durand", "01 23 45 67 89"),
            new Contact(2, "Paul Martin", "06 12 34 56 78"),
            new Contact(3, "Philippe Jandot", "02 98 76 54 32")));
    private int dernierId = 3;

    // synchronized : une seule requête à la fois exécute la méthode
    public synchronized List<Contact> liste() {
        return List.copyOf(contacts);
    }

    // Optional : un contact, ou "rien" s'il n'existe pas
    public synchronized Optional<Contact> lire(int id) {
        return contacts.stream().filter(c -> c.id() == id).findFirst();
    }

    public synchronized Optional<Contact> modifier(int id, String nom, String telephone) {
        for (int i = 0; i < contacts.size(); i++) {
            if (contacts.get(i).id() == id) {
                // un record est immuable : on le remplace par un nouveau
                Contact modifie = new Contact(id, nom, telephone);
                contacts.set(i, modifie);
                return Optional.of(modifie);
            }
        }
        return Optional.empty();
    }

    public synchronized Contact ajouter(String nom, String telephone) {
        Contact contact = new Contact(++dernierId, nom, telephone);
        contacts.add(contact);
        return contact;
    }

    public synchronized Optional<Contact> supprimer(int id) {
        Optional<Contact> contact = lire(id);
        contact.ifPresent(contacts::remove);
        return contact;
    }
}

    package exemple21.controllers;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.server.ResponseStatusException;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import exemple21.services.ContactsService;
import exemple21.services.ContactsService.Contact;

@Controller
@RequestMapping("/contacts")
public class ContactsController {

    private final ContactsService contacts;

    public ContactsController(ContactsService contacts) {
        this.contacts = contacts;
    }

    // un LIEN (<a href>) : une requête GET, qui ne modifie rien
    @GetMapping("")
    public String liste(Model model) {
        model.addAttribute("contacts", contacts.liste());
        return "contacts/liste";
    }

    @GetMapping("/{id:\\d+}")
    public String fiche(@PathVariable int id, Model model) {
        model.addAttribute("contact", contacts.lire(id).orElseThrow(ContactsController::introuvable));
        return "contacts/fiche";
    }

    // un BOUTON dans un formulaire POST : une requête qui modifie des données
    @PostMapping("/{id:\\d+}")
    public String enregistrer(@PathVariable int id, @RequestParam String nom, @RequestParam String telephone,
            RedirectAttributes redirection) {
        Contact contact = contacts.modifier(id, nom, telephone).orElseThrow(ContactsController::introuvable);
        redirection.addFlashAttribute("flash", "Le contact [" + contact.nom() + "] a été modifié.");
        return "redirect:/contacts";
    }

    // même formulaire, autre bouton (attribut formaction) : autre action
    @PostMapping("/{id:\\d+}/dupliquer")
    public String dupliquer(@PathVariable int id, @RequestParam String nom, @RequestParam String telephone,
            RedirectAttributes redirection) {
        Contact copie = contacts.ajouter(nom + " (copie)", telephone);
        redirection.addFlashAttribute("flash", "Le contact [" + copie.nom() + "] a été créé.");
        return "redirect:/contacts";
    }

    @PostMapping("/{id:\\d+}/supprimer")
    public String supprimer(@PathVariable int id, RedirectAttributes redirection) {
        Contact contact = contacts.supprimer(id).orElseThrow(ContactsController::introuvable);
        redirection.addFlashAttribute("flash", "Le contact [" + contact.nom() + "] a été supprimé.");
        return "redirect:/contacts";
    }

    // une exception qui produit une réponse 404
    private static ResponseStatusException introuvable() {
        return new ResponseStatusException(HttpStatus.NOT_FOUND, "contact inconnu");
    }
}

(() => {
  const modale = document.getElementById('modale-confirmation');
  const message = document.getElementById('modale-confirmation-message');
  let enAttente = null; // le formulaire à envoyer si l'on confirme

  // 1. on intercepte l'envoi des formulaires à confirmer
  document.querySelectorAll('form[data-confirmation]').forEach((formulaire) => {
    formulaire.addEventListener('submit', (evenement) => {
      evenement.preventDefault(); // l'envoi est suspendu
      enAttente = formulaire;
      message.textContent = formulaire.dataset.confirmation;
      modale.classList.remove('d-none'); // la fenêtre apparaît
    });
  });

  // 2. les deux boutons de la fenêtre
  modale.addEventListener('click', (evenement) => {
    const action = evenement.target.dataset.action;
    if (action === 'oui') {
      enAttente.submit(); // envoi, SANS redéclencher l'événement 'submit'
    } else if (action === 'non') {
      modale.classList.add('d-none');
      enAttente = null;
    }
  });
})();
